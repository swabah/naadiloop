# Monorepo with a single shared tRPC router as the only FE↔BE seam

Naadi's frontend (`apps/web`) and backend (`apps/server`) live in one pnpm-workspace monorepo and communicate exclusively through one exported `appRouter` in `packages/api`, rather than a REST/OpenAPI contract or independently-deployed services. We chose this over a decoupled multi-repo/REST setup because a 4-person, 4-hour build cannot absorb schema drift between frontend and backend — tRPC's inferred `AppRouter` type gives every caller full type-checking against the real procedure signatures with zero codegen step. The trade-off is tighter coupling (frontend and backend must ship from the same repo, same language) and no external API for third parties — both acceptable for a hackathon demo, revisit if Naadi ever needs a public API or non-TypeScript clients.
