# Single `encounters` table with a typed `kind` enum + `jsonb` payload, instead of one table per Encounter Kind

Diagnoses, prescriptions, lab results, immunizations, and procedures all live in one `encounters` table, distinguished by an `encounterKind` enum, with kind-specific fields in a `data: jsonb` column — instead of five normalized tables (`diagnoses`, `prescriptions`, `lab_results`, ...) each with their own typed columns. A future reader will reasonably assume the normalized-tables path, since it's the obvious one for a typed ORM (Drizzle) stack. We picked the single-table shape because the timeline (§6.6 of `PRD.md`) is fundamentally one chronological, filterable feed across all kinds, and five tables would mean five near-identical CRUD paths and a `UNION`-style query just to render one screen, for no reads-side benefit at this scale. The cost is losing column-level typing and constraints on the kind-specific fields inside `data` — acceptable because `zod` schemas at the tRPC input layer (`encounterSchema`, discriminated on `kind`) already enforce shape before anything reaches the DB. Revisit if a kind's structured fields need to be independently queried/indexed at scale (e.g., searching all lab results by test name across patients).
